# Human annotation infrastructure (Batch B, Phase 2)

A standalone, offline annotation study for KCC-Sahayak. It builds a frozen
300-query English sample from the existing corpus, gives each annotator a
single-file local interface, imports their labels into append-only shards, and
computes agreement **only when two independent people have labelled overlapping
items**.

No label in this directory is generated by a model. No expert has reviewed the
sample. Until real annotators submit sheets, every human result is **PENDING**.

## Hard rules

- Only new files under `experiments/annotation/` and `results/annotation/`.
- The existing corpus, models, `src/`, `backend/`, `frontend/`, scripts, Batch A
  and Phase 1 outputs are read-only.
- LLM labels that already exist in `data/annotation/annotated.csv` are used
  **only for stratification** and are stored separately in `key.jsonl`.
- No LLM fills a sheet or adjudicates a disagreement.
- Import is all-or-nothing: one invalid row rejects the whole file, so a sheet
  is never silently truncated.

## Sample

`build-sample` draws 300 English queries from `data/annotation/annotated.csv`
(3,496 real corpus rows) using these strata, assigned in priority order:

| Stratum | Rule |
|---|---|
| `potentially_unsafe` | query mentions a pesticide/fertiliser, a dose unit or a spray instruction |
| `insufficient_context` | symptom/pest named but no crop token and no corpus crop field |
| `ambiguous` | very short query, or a short `Other`-labelled query |
| `rare_intent` | Weather, Market Price, Fisheries, Cultural Practices |
| `novel` | no corpus question at >= 0.80 cosine similarity |
| `near_duplicate` | another corpus row in the same Batch A 0.95 group |
| `common` | a frequent category; also the filler for any shortfall |

Two dedupe rules: unique normalised question text, and no two selected queries
with cosine similarity >= 0.98. Novelty/group signals reuse the read-only Batch A
artefacts (`corpus_embeddings.npy`, `emb_annotated_texts.npy`,
`corpus_split.csv`); nothing is re-encoded.

Each item has three candidate answers: the query's logged answer plus one
same-topic and one different-topic distractor. Candidate provenance is stored
only in `key.jsonl`; annotators see `c1`, `c2`, `c3`.

## Labels

- **Intent**: `PP` Plant Protection, `NM` Nutrient Management, `WE` Weather,
  `GS` Government Scheme, `MP` Market Price, `VI` Varietal Information,
  `AH` Animal Husbandry, `FI` Fisheries, `CP` Cultural Practices, `OT` Other,
  `OOS` Out of scope.
  `OT` = agriculture question outside the nine topics; `OOS` = not about
  agriculture. The schema enforces agreement between `OOS` and
  `out_of_scope`.
- **Multi-intent**: optional list; must contain the primary intent.
- **Retrieval relevance** per candidate: `relevant`, `partially_relevant`,
  `irrelevant`, `cannot_judge`.
- **Answer quality** per candidate: `adequate`, `partially_adequate`,
  `inadequate`, `cannot_judge`.
- **Safety** (query) and **answer safety** (per candidate): `safe`, `caution`,
  `unsafe`, `cannot_judge`.
- **Missing context**: `crop`, `crop_stage`, `season`, `location`,
  `pest_or_disease`, `soil`, `none`.
- **Ambiguous**, **uncertain**, **certainty** 1–3, free-text notes.

## Workflow

```bash
# 1. build the frozen sample (writes items.jsonl, key.jsonl, sample_summary.json)
.venv312/bin/python experiments/annotation/cli.py build-sample

# 2. one offline page per annotator
.venv312/bin/python experiments/annotation/cli.py make-ui --annotator A001 A002

# 3. each annotator opens their own HTML file, fills it, exports JSON + CSV
# 4. import each sheet into that annotator's shard
.venv312/bin/python experiments/annotation/cli.py import --annotator A001 \
    experiments/annotation/data/exports/annotations_A001.csv

# 5. coverage and validation
.venv312/bin/python experiments/annotation/cli.py status
.venv312/bin/python experiments/annotation/cli.py validate

# 6. agreement (PENDING until two real sheets exist)
.venv312/bin/python experiments/annotation/cli.py agreement

# 7. adjudicate one disagreement (a named human, never the tool)
.venv312/bin/python experiments/annotation/cli.py adjudicate --item kcc-0001 \
    --task intent --label PP --adjudicator A003 --note "pest control is primary"

# 8. report + QC
.venv312/bin/python experiments/annotation/cli.py report --overwrite
```

## Data layout

```
experiments/annotation/
  data/
    items.jsonl          # blind items (safe to give to annotators)
    key.jsonl            # stratum, LLM label, source row, answer provenance
    sample_summary.json  # frozen selection statistics
    annotations/<A>.jsonl# append-only per-annotator shards
    adjudication.jsonl   # named human adjudications, append-only
    exports/             # JSON/CSV exports and rejected-import reports
    ui/<A>.html          # offline interface per annotator
results/annotation/
  REPORT.md  QC_REPORT.md
  agreement.json  qc.json  sample_overview.json
  tables/     # strata, LLM-label counts, confusion matrices
```

## Agreement methods

- Cohen's kappa per annotator pair, complete cases, with the number of items
  missing on each side reported.
- Fleiss' kappa for three or more annotators on items rated by all of them.
- Observed/expected agreement, confusion matrices, per-class one-vs-rest kappa
  with class support.
- Set-valued agreement (exact match, mean Jaccard) for multi-intent and
  missing-context; kappa is not defined for sets and is not reported for them.
- Human vs LLM comparison is separate and labelled as such.

Kappa is `null` (not 0) when expected agreement is 1, because it is undefined
there; the report shows `—` rather than inventing a value.

## Quality control

Missing items, blank tasks, duplicate revisions, invalid labels, structural
contradictions, long identical label runs between two annotators, and
adjudication status. Adjudication is tracked separately: a disagreement is
pending until a named human records `--status resolved`.

## Limitations

- English only in this pilot. The schema and UI support Hindi/Hinglish but no
  Hindi items were drawn; no cross-lingual claim is made.
- The sample is not a random sample of Indian farmers; it inherits the corpus's
  call-centre and annotation-pool biases.
- Candidate relevance is not live retrieval evaluation; Phase 6 evaluates the
  retriever on its own top-k.
- Agreement measures consistency, not correctness. Expert review is PENDING.
- The UI files contain real corpus text. They are local research files with no
  authentication; keep them on an authorised machine.
- The sample is frozen; rebuilding requires `--overwrite` and would invalidate a
  comparison with an earlier report.
